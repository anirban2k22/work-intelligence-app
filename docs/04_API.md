- **Status:** Implementation-ready
- **Base URL:** `/api/v1`
- **Reference docs:** `01_PRD.md`, `02_ARCHITECTURE.md`, `03_DATABASE.md`

## 1. API Conventions

### 1.1 Versioning & Base Path

- All endpoints are namespaced under `/api/v1`.
- API is **versioned** in the URL; breaking changes introduce `/api/v2` (NFR-8.2).
- OpenAPI/Swagger documentation is auto-generated by FastAPI and served at `/docs` in non-production environments.

### 1.2 Authentication

- **Authentication required** on every endpoint except `POST /auth/register`, `POST /auth/login`, and `POST /auth/forgot-password`.
- Auth uses **JWT access + refresh tokens** delivered as `HttpOnly`, `Secure`, `SameSite=Lax` cookies.
- Protected requests carry the cookie; the API resolves the user from the token.
- See `02_ARCHITECTURE.md` §6 for the full flow.

### 1.3 Data Format

- Request and response bodies are `application/json`.
- Dates are ISO-8601. Dates without time are `YYYY-MM-DD`; timestamps are `YYYY-MM-DDTHH:MM:SS.sssZ` (UTC).
- Durations (`hours`) are decimal hours, e.g. `1.5`.
- All strings are UTF-8.

### 1.4 Common Response Envelope

**Success:**

```json
{
  "data": { },
  "meta": { "request_id": "req_7f3a…" }
}
```

**Error envelope:**

```json
{
  "error": {
    "code": "validation_error",
    "message": "Field validation failed",
    "details": [
      { "field": "email", "message": "Must be a valid email address" }
    ],
    "request_id": "req_7f3a…"
  }
}
```

### 1.5 Pagination

List endpoints accept `page` (1-indexed, default `1`) and `page_size` (default `25`, max `100`).

```json
{
  "data": [ ],
  "meta": {
    "page": 1,
    "page_size": 25,
    "total": 142,
    "total_pages": 6
  }
}
```

### 1.6 Standard Error Codes

| HTTP | `code` | Meaning |
|------|--------|---------|
| 400 | `validation_error` | Request payload failed validation |
| 401 | `unauthenticated` | Missing or invalid credentials |
| 403 | `forbidden` | Authenticated but not allowed |
| 404 | `not_found` | Resource does not exist for this user |
| 409 | `conflict` | Version/state conflict (optimistic lock) |
| 410 | `gone` | Resource deleted or account pending deletion |
| 422 | `unprocessable_entity` | Semantically valid JSON but invalid domain state |
| 429 | `rate_limited` | Too many requests |
| 500 | `internal_error` | Server error |
| 502 | `ai_unavailable` | AI provider unavailable (graceful degradation) |
| 503 | `unavailable` | Service temporarily unavailable |

## 3. Authentication

### 3.1 Register

- **Purpose:** Create a new account, auto-create empty configuration, and establish a session.
- **Authentication:** None (public).

**Request** `POST /auth/register`

```json
{
  "email": "nadia@example.com",
  "password": "S3cure!Passw0rd",
  "display_name": "Nadia"
}
```

**Validation**

| Field | Rules |
|-------|-------|
| `email` | Required, valid email format, ≤ 320 chars, unique (409 if taken) |
| `password` | Required, 8–72 chars, at least one letter and one number |
| `display_name` | Optional, 1–120 chars |

**Response** `201 Created`

```json
{
  "data": {
    "user_id": 42,
    "email": "nadia@example.com",
    "display_name": "Nadia",
    "onboarding_complete": false
  },
  "meta": { "request_id": "req_…" }
}
```

**Errors:** `400 validation_error`; `409 conflict` (email already registered).

### 3.2 Login

- **Purpose:** Verify credentials and set auth cookies.
- **Authentication:** None.

**Request** `POST /auth/login`

```json
{
  "email": "nadia@example.com",
  "password": "S3cure!Passw0rd"
}
```

**Response** `200 OK` — Sets `access_token` (15 min) and `refresh_token` (30 days) cookies.

```json
{
  "data": {
    "user_id": 42,
    "email": "nadia@example.com",
    "display_name": "Nadia",
    "onboarding_complete": false
  }
}
```

**Errors:** `401 unauthenticated` (bad credentials); `429 rate_limited` (brute-force protection).

### 3.3 Logout

- **Purpose:** Revoke the refresh token and clear cookies.
- **Authentication:** Required.

**Request** `POST /auth/logout` — empty body.

**Response** `204 No Content`.

**Errors:** `401 unauthenticated`.

### 3.4 Forgot Password

- **Purpose:** Email a password-reset link.
- **Authentication:** None.

**Request** `POST /auth/forgot-password`

```json
{ "email": "nadia@example.com" }
```

**Response** `202 Accepted` — Always returns success even if email is unknown (prevents account enumeration).

### 3.5 Reset Password

- **Purpose:** Set a new password using a token from the reset email.
- **Authentication:** None (token acts as proof).

**Request** `POST /auth/reset-password`

```json
{
  "token": "reset_…",
  "password": "N3w!Password123"
}
```

**Response** `204 No Content`.

**Errors:** `400 validation_error`; `410 gone` (expired/invalid token).

### 3.6 Refresh

- **Purpose:** Rotate the access token using the refresh token.
- **Authentication:** Refresh token cookie.

**Request** `POST /auth/refresh` — empty body.

**Response** `200 OK` — New access token cookie, rotated refresh token cookie.

```json
{ "data": { "access_token_expires_in": 900 } }
```

**Errors:** `401 unauthenticated`.

**Response** `200 OK`

```json
{
  "data": {
    "log_date": "2026-08-07",

  }

```

**Errors:** `401 unauthenticated`.

### 5.2 Update Daily Log

- **Purpose:** Confirm a day or regenerate its AI summary.
- **Authentication:** Required.

**Request** `PATCH /daily-logs/{date}` — `date` is `YYYY-MM-DD`.

```json
{ "action": "confirm" }
```

`action`: `confirm` | `regenerate_summary`.

**Response** `200 OK`

```json
{
  "data": {

    "summary_ai": "…",
    "confirmed_at": "2026-08-07T18:04:00Z"
  }
}
```

**Errors:** `400 validation_error` (bad action); `409 conflict` (log already confirmed); `502 ai_unavailable` (on regenerate).

### 5.3 List Daily-Log Entries

- **Purpose:** Full entry list for a log with filters and pagination.
- **Authentication:** Required.

**Request** `GET /daily-logs/{date}/entries?status=confirmed&type=meeting&page=1&page_size=25`

**Response** `200 OK` (paginated list of entries; shape matches `GET /worklog/entries`).

## 6. Recording (Audio Upload)

### 6.1 Create Recording

- **Purpose:** Start an audio recording upload. Returns a signed upload URL and a recording ID; the client streams the audio to object storage.
- **Authentication:** Required.
- **Content type:** `application/json`.

**Request** `POST /recordings`

```json
{
  "filename": "friday-standup.m4a",
  "content_type": "audio/mp4",
  "size_bytes": 4821300,
  "session_id": null,
  "duration_seconds": 185
}
```

**Validation**

| Field | Rules |
|-------|-------|
| `filename` | Required, 1–255 chars, safe extension |
| `content_type` | Required, must be audio MIME (`audio/*`) |
| `size_bytes` | Required, `1 ≤ size ≤ 500MB` |
| `session_id` | Optional; must belong to the user if present |
| `duration_seconds` | Optional, `> 0` |

**Response** `201 Created`

```json
{
  "data": {
    "id": "rec_9f2b",
    "upload_url": "https://s3…/recordings/rec_9f2b.m4a?X-Amz-Signature=…",
    "status": "pending_upload",
    "expires_in": 900
  }
}
```

**Errors:** `400 validation_error`; `413 payload_too_large`.

### 6.2 Confirm & Transcribe Recording

- **Purpose:** Mark the upload as complete and enqueue Whisper transcription.
- **Authentication:** Required.

**Request** `POST /recordings/{id}/transcribe`

```json
{ "language": "en" }
```

**Response** `202 Accepted`

```json
{
  "data": {
    "id": "rec_9f2b",
    "status": "transcribing",
    "whisper_job_id": "wh_41e7"
  }
}
```

**Errors:** `404 not_found`; `409 conflict` (upload not finalized); `502 ai_unavailable`.

### 6.3 Get Recording

- **Purpose:** Poll recording status and retrieve transcript when ready.
- **Authentication:** Required.

**Request** `GET /recordings/{id}`

**Response** `200 OK`

```json
{
  "data": {
    "id": "rec_9f2b",
    "status": "transcribed",
    "transcript_text": "Reviewed the release candidate with the platform team…",
    "transcript_segments": [
      { "start": 0.0, "end": 12.4, "text": "Reviewed the release candidate with the platform team…", "speaker": null }
    ],
    "whisper_job_id": "wh_41e7"
  }
}
```

**Errors:** `404 not_found`.

## 7. Whisper Processing

### 7.1 Transcribe Audio

- **Purpose:** Direct transcription of an uploaded audio blob (used when the client uploads inline).
- **Authentication:** Required.
- **Content type:** `multipart/form-data` with field `audio` and optional `language`.

**Request** `POST /whisper/transcribe`

| Form field | Rules |
|------------|-------|
| `audio` | Required, file, `audio/*`, ≤ 500MB |
| `language` | Optional, BCP-47 (`en`, `en-US`); defaults to auto-detect |
| `prompt` | Optional, guiding vocabulary (e.g., configured entity names) |

**Response** `202 Accepted` (async job)

```json
{
  "data": {
    "job_id": "wh_41e7",
    "status": "queued"
  }
}
```

**Errors:** `400 validation_error`; `502 ai_unavailable`.

### 7.2 Get Whisper Job

- **Purpose:** Poll transcription job status.
- **Authentication:** Required.

**Request** `GET /whisper/jobs/{id}`

**Response** `200 OK`

```json
{
  "data": {
    "job_id": "wh_41e7",
    "status": "completed",
    "text": "…",
    "segments": [
      { "start": 0.0, "end": 12.4, "text": "…", "speaker": null }
    ],
    "language": "en",
    "duration_seconds": 185,
    "error": null
  }
}
```

`status`: `queued` | `processing` | `completed` | `failed`.

**Errors:** `404 not_found`.

## 8. AI Extraction (Capture Sessions)

### 8.1 Create Capture Session

- **Purpose:** Start a conversational capture session.
- **Authentication:** Required.

**Request** `POST /capture/sessions`

```json
{
  "source": "chat",
  "title": "Friday review"
}
```

**Response** `201 Created`

```json
{
  "data": {
    "id": 15,
    "source": "chat",
    "title": "Friday review",
    "status": "open"
  }
}
```

**Errors:** `400 validation_error`.

### 8.2 Submit Message

- **Purpose:** Submit a natural-language work description. Accepts a reference to a completed transcript (voice capture) or raw text (typed/pasted).
- **Authentication:** Required.
- **Behavior:** Persists the message, enqueues extraction, and returns draft entries with confidence and provenance. Clarifications arrive as a follow-up event (see §8.4).
- **Performance:** Initial structured results target < 10 s p95 (NFR-1.1); extraction runs in the worker tier.

**Request** `POST /capture/sessions/{id}/messages`

```json
{
  "content": "Reviewed the Phoenix release candidate with the platform team, shipped the API docs update, and had a 1:1 with David about the onboarding timeline. Spent about 3 hours total.",
  "recording_id": "rec_9f2b"
}
```

`content` or `recording_id` is required (at least one; both is allowed — content overrides).

**Response** `201 Created` — draft entries:

```json
{
  "data": {
    "message_id": 812,
    "entries": [
      {
        "id": 901,
        "status": "draft",
        "entry_type": "deliverable",
        "summary": "Reviewed the Phoenix release candidate",
        "details": "Reviewed with the platform team.",
        "kra": { "id": 3, "name": "Platform Architecture", "confidence": 0.97, "inferred": false },
        "project": { "id": 7, "name": "Project Phoenix", "confidence": 0.95, "inferred": false },
        "stakeholders": [
          { "id": 21, "name": "Platform Team", "engagement": "participated", "confidence": 0.9, "inferred": false }
        ],
        "hours": 1.5,
        "work_date": "2026-08-07",
        "overall_confidence": 0.88,
        "clarifications": null,
        "provenance": { "message_id": 812, "span_start": 0, "span_end": 58 }
      }
    ],
    "clarifications": []
  }
}
```

**Errors:** `400 validation_error`; `404 not_found`; `502 ai_unavailable` (LLM down — manual entry remains available).

### 8.3 Get Session

- **Purpose:** Retrieve full conversation and extraction history.
- **Authentication:** Required.

**Request** `GET /capture/sessions/{id}`

**Response** `200 OK` — messages, entries with provenance, clarifications, status.

### 8.4 Clarify

- **Purpose:** Answer the AI's clarifying question to resolve ambiguity; triggers re-extraction of the affected entries.
- **Authentication:** Required.

**Request** `POST /capture/sessions/{id}/clarify`

```json
{
  "message_id": 812,
  "clarification_id": "cl_5aa1",
  "answers": { "project_id": 7, "kra_id": 3 }
}
```

**Response** `200 OK` — updated entries with revised confidence:

```json
{
  "data": {
    "entries": [
      {
        "id": 901,
        "overall_confidence": 0.96,
        "project": { "id": 7, "name": "Project Phoenix", "confidence": 0.99, "inferred": false }
      }
    ]
  }
}
```

**Errors:** `404 not_found`; `409 conflict` (clarification already resolved).

**Response** `200 OK` (paginated)

```json
{
  "data": [
    {
      "id": 901,
      "entry_type": "meeting",
      "summary": "Weekly program sync",
      "details": null,
      "kra": { "id": 1, "name": "Stakeholder Management" },

      "status": "confirmed",
      "work_date": "2026-08-07",
      "is_ai_generated": true,
      "created_at": "2026-08-07T09:12:00Z",
      "updated_at": "2026-08-07T10:00:00Z"
    }
  ],
  "meta": { "page": 1, "page_size": 25, "total": 17 }
}
```

### 9.2 Update Entry

- **Purpose:** Confirm, edit, reject, split, or merge entries. Corrections feed the learning loop.
- **Authentication:** Required.
- **Concurrency:** Requires `version`; stale writes return `409 conflict` (FR-5, §03-DB §5.4).

**Request** `PATCH /worklog/entries/{id}`

```json
{
  "version": 1,
  "status": "confirmed",
  "summary": "Weekly program sync with platform leads",
  "hours": 1.25,
  "kra_id": 3,
  "project_id": 7,
  "stakeholder_ids": [5, 21],
  "entry_type": "meeting"
}
```

All fields optional except `version`. Supported transitions: `draft → confirmed`, `draft → archived` (reject), `confirmed → archived`.

**Response** `200 OK` — updated entry.

**Errors:** `400 validation_error`; `404 not_found`; `409 conflict` (version mismatch or invalid transition).

### 9.3 Create Manual Entry

- **Purpose:** Fallback manual entry when the user prefers typed form input (NFR-2.3 degradation path).
- **Authentication:** Required.

**Request** `POST /worklog/entries/manual`

```json
{
  "work_date": "2026-08-07",
  "entry_type": "documentation",
  "summary": "Updated API docs for webhooks",
  "details": "Added webhook retry semantics.",
  "kra_id": 3,
  "project_id": 7,
  "stakeholder_ids": [],
  "hours": 2.0
}
```

**Response** `201 Created` — entry with `status: confirmed`, `is_ai_generated: false`.

**Errors:** `400 validation_error`.

## 10. Reports

### 10.1 Generate Report

- **Purpose:** Kick off asynchronous report generation (daily/weekly/custom).
- **Authentication:** Required.

**Request** `POST /reports`

```json
{
  "report_type": "weekly",
  "start_date": "2026-08-03",
  "end_date": "2026-08-07",
  "template_id": 4
}
```

**Validation:** `report_type` required (`daily`|`weekly`|`custom`); `start_date ≤ end_date`; `template_id` optional, must belong to user.

**Response** `202 Accepted`

```json
{
  "data": { "id": 88, "status": "generating" }
}
```

**Errors:** `400 validation_error`; `404 not_found`; `502 ai_unavailable`.

### 10.2 Get Report

- **Purpose:** Fetch report content once ready.

**Request** `GET /reports/{id}`

**Response** `200 OK`

```json
{
  "data": {
    "id": 88,
    "report_type": "weekly",
    "title": "Weekly Report — Aug 3–7, 2026",
    "status": "ready",

    "end_date": "2026-08-07"

}
```

### 10.3 Update Report

- **Purpose:** Edit report content before export.
- **Authentication:** Required.

**Request** `PATCH /reports/{id}`

```json
{ "content_markdown": "# Edited…", "version": 2 }
```

**Response** `200 OK` — updated report.

### 10.4 Export Report

- **Purpose:** Generate a downloadable artifact (Markdown/PDF).
- **Authentication:** Required.

**Request** `GET /reports/{id}/export?format=pdf`

**Response** `200 OK` — binary stream with `Content-Disposition: attachment`.

### 10.5 List Reports

- **Purpose:** Paginated report history.
- **Authentication:** Required.

**Request** `GET /reports?type=weekly&page=1&page_size=25`

## 19. Cross-Cutting Behaviors

| Concern | Behavior |
|---------|----------|
| **Idempotency** | Mutating endpoints accept an optional `Idempotency-Key` header; retries with the same key return the same result |
| **Rate limiting** | Auth endpoints and AI-capture endpoints rate-limited per user/IP (Redis); `429 rate_limited` |
| **Audit** | Every mutation logs actor, resource, before/after snapshot (for the learning loop and compliance) |
| **Optimistic locking** | `work_entries` and `reports` use `version`; config entities use `updated_at` comparison |
| **Graceful degradation** | When the AI provider is unavailable: `POST …/messages`, `…/transcribe`, and `…/extract` return `502 ai_unavailable`; all manual entry/review/report-read endpoints stay fully functional (NFR-2.3) |
| **Pagination & filters** | All list endpoints standardize on `page`/`page_size` and filter params listed per endpoint |
